# 1. מעבר עסק וארגון Clerk

1.1 בביקורת מ־12.09.2026 נמצא שבחירת עסק שמרה את `tenant_selections` אך לא החליפה את הארגון הפעיל ב־Clerk. לאחר מעבר לעסק אחר, בדיקת התאמת הארגון ב־API חסמה את המשתמש. רענון React בלבד גם השאיר טיוטות מקומיות של העסק הקודם.

# 2. הכרעות

2.1 **שמירת בחירה → הפעלת הארגון → טעינה מחדש.** השרת פותר את מפתח הבחירה מול חברויות פעילות וקורא את מיפוי הארגון ממסד הנתונים. רק אחרי הצלחת שמירת הבחירה מחזירים לדפדפן את הארגון להפעלה. שתי נקודות הכניסה בממשק ממתינות ל־`Clerk.setActive()` לפני דיווח הצלחה וטעינה מלאה שמנקה טיוטות ומצב מקומי.

2.2 **התאוששות באמצעות בחירה חוזרת.** שמירת הבחירה והפעלת Clerk אינן טרנזקציה משותפת. אם ההפעלה נכשלה או נקטעה, ספריית העסקים מזהה את חוסר ההתאמה ומחזירה את מסך הבחירה עם גרסת הבחירה הנוכחית, גם כאשר נותר עסק יחיד. אין ביטול אוטומטי של בחירה שכבר נשמרה. אפשר לבחור מחדש או לבחור עסק אחר.

2.3 **שמירת בידוד העסק.** ה־API ממשיך לבדוק חברות, בחירה ומיפוי מול הארגון שב־Session החתום. הארגון המוחזר הוא יעד הפעלה לדפדפן; הוא אינו הרשאה עסקית. מיפוי חסר או שגוי עוצר את השמירה. שינוי בחירה או ביטול חברות בחלון אחר עדיין מחייב בדיקת שרת עדכנית.

2.4 **חריג תגובה מצומצם.** `organizationId` מותר רק בתגובת `tenant-selection.save` ובמבנה המדויק של הצלחת הבחירה. מנגנוני השרת והלקוח יודעים איזו פעולה בוצעה. השדה נשאר אסור בכל בקשה, בפעולות אחרות, בשדות מקוננים ובמבנה מורחב. אין החזרת מזהה עסק, משתמש, Session או סוד. בחירה אינה מקבלת מזהה ארגון מהלקוח.

2.5 **איפוס הממשק לפי העסק שנבחר.** עץ סביבת העבודה מקבל מפתח React מתוך מפתח הבחירה הקיים. גם רענון מהשרת בעקבות החלפה בחלון אחר אינו משמר את עץ הטיוטות של העסק הקודם. מצב ללא חיבור Clerk ממשיך להיטען בלי הפעלת Hook שדורש Provider.

# 3. אימות ומגבלות

3.1 בדיקות ממוקדות מכסות את המסלול דרך פעולת השרת, החלפת הארגון ומתאם הרשאות העסק; כשל והמשך עם גרסה חדשה; עסק יחיד; מיפוי חסר או שגוי; המתנה להפעלה; חסימת שדות זהות בבקשות ובתגובות לא מתאימות; וחיבור שתי נקודות הכניסה בממשק. אלו בדיקות אוטומטיות עם תשתית הבדיקות הקיימת, ללא שימוש בחשבון משתמש חי.

3.2 לפני קבלה חיה יש לבדוק משתמש אמיתי בשני עסקים ובשתי לשוניות, תפוגת Session וביטול חברות. סיום הבדיקות המקומיות אינו הוכחה לשילוב Clerk/Railway ב־Staging. לא השתנו מיגרציות, תלויות או מנגנון התאמת הארגון להרשאות העסק.

3.3 השרת ו־Web צריכים להיפרס מאותה גרסה. גרסה קודמת אינה מכירה את שדה ההפעלה בתגובה; פריסה מעורבת תיחסם במקום לדווח מעבר מוצלח. יש לפרוס את מועמד התיקון שנבדק, ולא את גרסת PR 26 לבדה.

3.4 מקור API שנבדק ב־12.09.2026: [Clerk — setActive](https://clerk.com/docs/nextjs/reference/objects/clerk#set-active), [Clerk — useClerk](https://clerk.com/docs/nextjs/reference/hooks/use-clerk). התיעוד מגדיר הפעלת ארגון; סדר השמירה, ההתאוששות ובידוד הנתונים הם החלטות המימוש של Connect.
