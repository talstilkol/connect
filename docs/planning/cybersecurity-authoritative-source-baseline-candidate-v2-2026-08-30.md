# 2. Source-role model

## 2.1 Required separation

2.1.1 `Governance Source` defines risk-management structure and accountability.

2.1.2 `Control Source` defines control objectives or safeguards.

2.1.3 `Verification Source` defines testable requirements.

2.1.4 `Threat Source` defines attack paths, adversary behavior or risk categories.

2.1.5 `Maturity Source` structures improvement but does not prove release security.

2.1.6 `Provenance Source` defines integrity and origin claims but does not prove artifact safety.

2.1.7 `Vendor Contract Source` defines current platform behavior or entitlement but cannot substitute for account readback.

2.1.8 `Legal Source` defines potential obligations but requires applicability analysis and counsel approval.

2.1.9 `Operational Evidence` proves a control operated on the exact environment and exact subject.

2.1.10 one source may serve multiple roles, but each claimed role must be separately declared and tested.

## 2.2 Evidence ladder

2.2.1 level `0`=`URL or prose mention only`.

2.2.2 level `1`=`dated read observation with claim limit`.

2.2.3 level `2`=`captured exact bytes plus digest and retrieval receipt`.

2.2.4 level `3`=`two independent readers reproduce identity and semantic extraction`.

2.2.5 level `4`=`derived requirement crosswalk plus negative Tests`.

2.2.6 level `5`=`environment-bound operational Evidence and independent Gate review`.

2.2.7 this candidate’s maximum evidence level=`1`.
